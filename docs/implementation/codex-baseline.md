## Architecture and contracts

- The Java 21 Maven reactor has 13 modules. `core` owns the listing and finding types. `rule-engine` runs versioned marketplace rules. `trademark-scanner`, `variation-checks`, `personalization-screening`, and `image-checker` own their pack logic. `listing-input-adapters` parses supported imports. `rag-analyzer` owns policy parsing, chunking, retrieval and model interfaces, and citation verification.
- `api` is the Spring Boot 4.1 host for REST, the Web Console, and operator jobs. PostgreSQL 16 with pgvector backs checks and policy retrieval. Flyway owns schema changes. Pack services own client-scoped result lookup, cache identity, plans, quota, and retention. Use their entry points when adding a workflow that calls existing packs. [Architecture guide](../overview.md) · [ADR-010](../adr/ADR-010-pack-identity-and-analysis-version.md)
- The public contract is checked in as [OpenAPI](../api/openapi.json) and [input JSON Schema](../api/input-schema.json). `OpenApiIntegrationTest` checks the live API description, `contract-tools` checks compatibility against the versioned release baseline, and `client` checks typed Java DTO conformance. `mcp-server` calls REST through the Java SDK and its tool catalog also constrains the bundled agent skill. An API change can require coordinated contract, SDK, and MCP changes if the operation is exposed there. [ADR-022](../adr/ADR-022-api-contract-and-compatibility.md) · [ADR-023](../adr/ADR-023-java-client-sdk.md) · [MCP guide](../mcp.md)
- The optional Web Console uses Spring MVC controllers, Thymeleaf, shared finding cards and layout fragments, and local CSS and scripts. It operates as the signed-in account's client through a server-side session with CSRF protection. Console sessions support magic-link sign-in and verified Cloudflare Access assertions. Public check endpoints use client API keys. [ADR-027 (Accepted)](../adr/ADR-027-console-access-login.md) English and Vietnamese message and rule bundles must stay in sync; copy from JavaScript comes through template attributes. Design tokens originate under `docs/design/`, and the shared shell and components serve the work and manage pages. [ADR-028](../adr/ADR-028-console-localization.md) · [ADR-040](../adr/ADR-040-console-visual-identity-and-design-system.md) · [ADR-041](../adr/ADR-041-console-work-pages.md) · [ADR-042 (Accepted)](../adr/ADR-042-console-manage-pages.md)
- Flyway migrations are under `api/src/main/resources/db/migration/` and reach V42. Roadmap touchpoints include V3 (policy corpus), V7–V14 (pack identity), V17–V20 (trademark checks, plans and quota, fixes and readiness), V21 and V35 (console accounts and access), V22–V25 (variation and personalization), V29–V30 (image checks), V33 (policy snapshots), V37 (finding verdicts), V38 (watchlist), V39 (check history), V40 (re-audit), V41 (LLM usage), and V42 (rewrite run metadata). The relevant persistence units are `policy_document` and `policy_chunk`, the policy monitor document and section hashes, `finding_verdict`, `check_history_event`, `reaudit_run` and `reaudit_run_row`, `llm_usage`, and `rewrite_suggestion_run`. Apply new schema changes in additive migrations after the latest version then current on main. [Deployment and migration procedures](../deployment.md)

## Recommended PR sequence

1. **Risk Resolution UX.** Use existing pack results, edit grouping, history references and verdict targets. Add user-flow coverage for new, modified, resolved and unavailable results in both locales.
2. **Policy Intelligence.** First review the labelled retrieval queries and record actual evaluation on a versioned corpus. Follow with provider/profile integration and citation checks using stubs, then a separately reviewed, default-off contract and analyzer evaluation.
3. **Verified Case Intelligence.** Start source and terms review in parallel with retrieval evaluation. After maintainer decisions on sources, commercial reuse and evidence display, build offline reviewed fixtures and versioned case links. Keep any scoring change a separate decision.
4. **Policy Change Impact.** Reuse the diff job and reviewed source-to-rule references. Start with an operator review output, then decide how to expose confirmed impact and when to prompt a client to re-audit.
5. **POD Readiness.** Gather workshop profiles and review source coverage early. Define the readiness result after pack prerequisites are met, then compose the existing pack outputs with clear applicability and incomplete states. Treat image-upload enablement as a separate operational gate.

## Risks and verification gates

- Tenant and retention boundaries matter across check history, feedback, re-audit, and case evidence. Verify cross-client and expired IDs, cache and quota behavior, note visibility, and storage of only the metadata each workflow needs.
- Source rights, mark-link accuracy, and policy freshness gate the intelligence tracks. Cite reviewed versions and preserve explicit uncertainty. Keep changes in immutable ruleset/catalog versions and never infer a clean result from missing evidence.
- Pin model and corpus identity, keep real-provider evaluation separate from fixture-based tests, and require explicit decisions on third-party processing of client data. Avoid widening provider data permissions as part of UI work.
- CI runs the full reactor on Java 21. API integration tests use Testcontainers and `pgvector/pgvector:pg16`, with deterministic hashing or local stubs in place of live models. Relevant suites include `ListingEditAndHistoryIntegrationTest`, `FeedbackApiIntegrationTest`, `ConsoleReauditIntegrationTest`, `PolicyRetrievalIntegrationTest`, `PolicyDiffEngineTest`, `CitationVerifierTest`, `ListingRewriterIntegrationTest`, and Console localization, CSS and accessibility tests. `ListingEvalGateTest` checks the versioned listing evaluation baseline. CI also builds the SDK release JARs and builds the release image on PRs and main. [.github/workflows/ci.yml](../../.github/workflows/ci.yml)

## Test evidence

The initial Cloud invocations of the full Maven gate exited 1 before tests:

| Invocation | Result |
| --- | --- |
| `./mvnw -B verify` | The wrapper could not create `/home/agent/.m2` on the read-only filesystem. |
| `./mvnw -B verify` with a writable Maven home/local repository, then with JVM HTTP(S) proxy properties | Both attempts failed to resolve the Jackson 2.23.0 and Spring Boot 4.1.2 BOMs because Maven Central was unreachable. |
| `./mvnw -B -s /tmp/lg00-maven/settings.xml verify` with a Maven proxy and writable home, then with the system Java 21 location explicitly set | Both attempts reached compilation and failed in `core` with `release version 21 not supported`. The preinstalled Java runtime lacked `javac` and `lib/ct.sym`. |

A Debian OpenJDK 21.0.13 compiler and runtime were assembled in `/tmp` using the matching JDK package and installed runtime. The verification commands used `JAVA_HOME=/tmp/lg00-jdk/usr/lib/jvm/java-21-openjdk-amd64`, that JDK on `PATH`, and `MAVEN_USER_HOME=/tmp/lg00-maven`. The Maven settings file directs Maven Central traffic through the Cloud proxy and keeps the cache in `/tmp`.

On the clean base with that JDK, `./mvnw -B -s /tmp/lg00-maven/settings.xml verify` exited 1 in API integration tests. Docker returned HTTP 500 with `no space left on device` while creating pgvector containers in its VFS storage. The reactor passed through the Java client SDK. The MCP server, contract tools and Hugging Face converter were skipped in that run.

A clean-base retry with `./mvnw -B -s /tmp/lg00-maven/settings.xml -Dspring.test.context.cache.maxSize=1 verify` kept fewer Spring contexts open. PostgreSQL still reported SQLSTATE `53100` during Flyway migrations when standalone integration-test containers overlapped with a cached Spring context. The run was stopped after those errors and exited 143.

The full feature-branch gate exited **0** using `./mvnw -B -s /tmp/lg00-maven/settings.xml -DreuseForks=false -Dspring.test.context.cache.maxSize=1 verify`. Surefire used a separate test JVM per class to release PostgreSQL containers between classes. All 13 modules succeeded. Maven reported 3,239 tests, 0 failures, 0 errors and 2 assumption skips. The skipped RAG tests require locally saved raw policy files (`RealCorpusParseTest` and one `EvalLabelsTest` case). No real provider or raw policy corpus evaluation was run.
