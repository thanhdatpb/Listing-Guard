# Listing Guard v0.6.0

Released 2026-11-07. Changes since v0.5.0. This release adds two analysis packs, marketplace ruleset updates, a listing
health report, an MCP server for AI agents, and a production deployment path for ARM64 hosts. **Read the
[upgrade notes](#upgrade-notes) before you deploy.** Migrations V22 through V27 are additive, but an older image does
not undo them.

## What is new

### Amazon and Etsy rulesets

The active Amazon ruleset is `amazon-2026-12b`; `amazon-2026-12` remains unchanged as history. Within one month, a later
Amazon ruleset revision uses a letter suffix (`12b`, then `12c`). Amazon's title limit is now 75 characters and produces
a WARNING. `item_highlights_length` checks the 125-character Item Highlights limit, also as a WARNING, and
`prohibited_content` now scans `item_highlights` as well as title, description and bullet points.

`amazon-2026-12b` adds checks for Amazon Custom input: at most 10 text inputs across print surfaces, at most 100
dropdown options per print surface, and at most 10 customer-uploaded images per print surface. It also checks for a
missing seller-defined `max_chars` and gives an INFO reminder for sensitive free-text fields such as name, number, team
or player. Source status is recorded per rule; see [Known limits](#known-limits).

The active Etsy ruleset is `etsy-2026-12`. It adds structured personalization-question checks and title guidance for
word count, repeated words and promotional terms. `banned_words` is switched off because its word list had no source.
These changes are in the versioned ruleset; prior versions remain unchanged.

### Ruleset limits endpoint

`GET /api/v1/rulesets/{marketplace}/limits` returns the numeric limits declared by each active rule, including field,
unit, severity, source status and whether the rule is enabled. It supports `ETag`/`If-None-Match` and a five-minute
private cache. Limits come from each rule's `Rule.limits(settings)` declaration; the console editor counters use the same
service. The endpoint is read-only and requires an API key, but no plan pack or quota unit.

### Variation checks (ADR-015)

The `variation-checks` pack has its own Java module and endpoints: `POST /api/v1/variation-checks` and
`GET /api/v1/variation-checks/{id}`. It checks Amazon and Etsy variation families without editing or publishing them.
Migration V22 adds the plan pack and V23 creates the result and finding tables. When plan enforcement is enabled, the
pack is seeded for `SELLER` and `PRO`, not `FREE`. Results are retained for 30 days by default; the request family is
not stored.

### Personalization screening (ADR-016)

The `personalization-screening` pack checks buyer-entered personalization text against the configured print profile
and trademark catalog. Its endpoints are `POST /api/v1/personalization-screenings` and
`GET /api/v1/personalization-screenings/{id}`. Migration V24 adds the plan pack and V25 creates the result and finding
tables. When plan enforcement is enabled, the pack is seeded for `SELLER` and `PRO`, not `FREE`. Results are retained
for 30 days by default; the submitted text is not stored. See [Known limits](#known-limits) before relying on print
character findings.

### Listing health report (ADR-018)

`GET /api/v1/reports/summary`, the signed-in `/console/report` page, and the one-shot `health-report` job use the same
read-only report service. The report aggregates stored listing-rule, trademark, variation and personalization results;
it does not read client-entered text, write a rollup table, count cache hits or charge quota. The job writes
`report.json` and `report.html` files. Use `--client=<name-or-id>` for one client or `--all-clients` for every active
client. The default period is the seven complete UTC days before today; a requested period can span at most 92 days,
inclusive.

### Console API key management (ADR-014 B4a)

The optional console now has an **API keys** page at `/console/api-keys` to list, create and revoke keys for the signed-in
client. A new secret is shown once; keys created by the admin job count toward the same default limit of five active
keys. The page has no plan gating or migration.

### MCP server for AI agents (ADR-017)

The new `mcp-server` Maven module is a thin client of the Listing Guard REST API. It exposes six tools:
`check_listing`, `check_trademark`, `check_variations`, `screen_personalization`, `get_limits` and `get_usage`.
STDIO is the default transport; optional Streamable HTTP is disabled by default. The standalone shaded jar is built
with `./mvnw -B -pl mcp-server package`. For this release, the maintainer must attach it manually to the GitHub
Release as `listing-guard-mcp-0.6.0.jar`; the image workflow does not upload the jar. See [MCP server
documentation](../mcp.md).

### Production deployment and ARM64 images (ADR-019)

The production Compose setup now includes trademark import/conversion and batch jobs, plus the `health-report` job in
the `tools` profile. The optional [shared-network override](../../docker-compose.prod.shared-network.yml) lets a
trusted same-host Preview container reach the API without publishing another port. Resource defaults cap the API at
2 GB and PostgreSQL at 4 GB, with 2 GB `shared_buffers`, 16 MB `work_mem` and 50 connections. JSON-file logs are
rotated. The API remains bound to `127.0.0.1`; PostgreSQL has no published host port.

The [cloudflared override](../../docker-compose.prod.cloudflared.yml) adds the pinned Cloudflare connector image and
requires `TUNNEL_TOKEN`. Configure the Cloudflare public hostname to route to `http://api:8080` over the private
Compose network. The [Oracle A1 runbook](../deploy-oracle.md) also documents Cloudflare Access for `/console/*`,
backup/restore, monitoring and moving to another host. ADR-019 remains Proposed; the guide is not evidence of a live
Oracle or Cloudflare deployment.

The [Dockerfile](../../Dockerfile) builds the Java artifact on `$BUILDPLATFORM` and runs it on `$TARGETPLATFORM`,
copies the `mcp-server` module into the Maven build context, and avoids running Maven under QEMU. The
[release workflow](../../.github/workflows/release-image.yml) scans the amd64 image with Trivy, then publishes
`linux/amd64` and `linux/arm64` manifests for both the version and `latest` tags.

## Breaking changes

There is no breaking request-shape change to the existing check endpoints, but some results and operator behavior
change:

- **Amazon and Etsy cache identity changes.** The active Amazon and Etsy ruleset versions change to
  `amazon-2026-12b` and `etsy-2026-12`; the resulting `analysisVersion` changes, so cached results from the previous
  ruleset versions are not reused.
- **Amazon title findings change.** Titles over 75 characters now produce a WARNING (the previous Amazon ruleset used
  200 characters).
- **Etsy `banned_words` no longer runs.** Listings that previously received this sample-list warning will not receive
  it under `etsy-2026-12`.
- **Production resource defaults are lower and explicit.** The production Compose file now caps API/PostgreSQL memory
  and sets PostgreSQL tuning defaults. Adjust the environment values for hosts with less memory or larger capacity.
- **Health-report all-client syntax is explicit.** Replace `--client=all` with `--all-clients`; `--client=all` now
  names a client literally called `all`.

New packs and report surfaces use separate endpoints; they do not change the existing `/api/v1/checks` or
`/api/v1/trademark-checks` request shapes.

## Upgrade notes

### Database migrations

Flyway applies pending migrations at API startup. Back up the database before upgrading.

| Migration | Change |
| --- | --- |
| V22 | Adds `variation-checks` to the allowed plan packs and seeds it for `SELLER` and `PRO`. |
| V23 | Creates `variation_check` and `variation_check_finding`. |
| V24 | Adds `personalization-screening` to the allowed plan packs and seeds it for `SELLER` and `PRO`. |
| V25 | Creates `personalization_screening` and `personalization_screening_finding`. |
| V26 | Creates four `(client_id, created_at)` report indexes using `CREATE INDEX CONCURRENTLY`, outside a transaction. |
| V27 | Fails the migration if any index created by V26 is missing or invalid. |

These migrations do not roll themselves back. Starting an older image does not undo them; restore a pre-upgrade backup
to roll back the database.

### Production environment and Compose

The [production environment template](../../deploy/env.prod.example) adds these settings:

| Variables | Default or use |
| --- | --- |
| `API_MEM_LIMIT`, `JAVA_TOOL_OPTIONS` | `2g` and `-XX:MaxRAMPercentage=75.0` for the API. |
| `POSTGRES_MEM_LIMIT`, `POSTGRES_SHARED_BUFFERS`, `POSTGRES_WORK_MEM`, `POSTGRES_MAX_CONNECTIONS` | `4g`, `2GB`, `16MB` and `50`. Increase for a larger host; leave OS and container headroom. |
| `TUNNEL_TOKEN` | Required only when the cloudflared override is selected. Keep it secret. |
| `BACKUP_RETENTION_COUNT` | Local dump retention; defaults to 14. |
| `BACKUP_S3_BUCKET`, `BACKUP_S3_PREFIX`, `BACKUP_S3_ENDPOINT`, `BACKUP_S3_REGION`, `BACKUP_S3_ACCESS_KEY_ID`, `BACKUP_S3_SECRET_ACCESS_KEY`, `BACKUP_S3_SESSION_TOKEN` | Optional S3-compatible off-host backup configuration; the Oracle runbook documents Cloudflare R2. |
| `TRADEMARK_CATALOG_VERSION` | Empty by default; set to an imported catalog version to enable trademark checks in production. |
| `LISTING_GUARD_SHARED_NETWORK` | Only needed with the shared-network override. |
| `COMPOSE_FILE` | Optional colon-separated Compose files for operator commands and backup/restore scripts. |

Plan enforcement, fixes/readiness and the console remain off by default. Cloudflare Tunnel and the shared network are
opt-in Compose overrides. To start the base production services:

```bash
docker compose -f docker-compose.prod.yml --profile prod up -d
```

For Tunnel, include both files and keep them selected for subsequent commands:

```bash
docker compose -f docker-compose.prod.yml -f docker-compose.prod.cloudflared.yml --profile prod up -d
```

Add `-f docker-compose.prod.shared-network.yml` only when a trusted Preview container needs same-host private access.
When using any override, keep all selected `-f` files in `up`, `pull` and other Compose operations (or set
`COMPOSE_FILE` in `.env`).

Production one-shot jobs use both profiles; for example:

```bash
docker compose -f docker-compose.prod.yml --profile prod --profile tools run --rm health-report --all-clients
```

The trademark import, USPTO converter and batch job use the same `--profile prod --profile tools` invocation pattern.
The production batch service receives `LISTING_GUARD_FIXES_ENABLED`, matching the API's configured fixes behavior.

### New routes and feature defaults

The variation and personalization packs are separate additions; plan enforcement is still off unless
`LISTING_GUARD_PLANS_ENABLED=true`. `LISTING_GUARD_FIXES_ENABLED` and `LISTING_GUARD_CONSOLE_ENABLED` also default to
false in production. The ruleset limits endpoint is read-only. MCP starts in STDIO mode; set
`LISTING_GUARD_MCP_TRANSPORT=http` only when HTTP is needed, and keep it on loopback or a trusted private network.

## Known limits

- **Personalization print profiles are placeholders.** `latin_basic` and `latin_extended` use invented values. The
  workshop's real print profile remains open in [ADR-016](../adr/ADR-016-personalization-screening.md), open question 1.
- **Amazon Custom and variation rules are not fully verified.** Amazon Custom count thresholds come from secondary
  sources; its `max_chars` and sensitive free-text reminder are unverified. Variation rules mix secondary sources and
  unverified values; findings carry their source status.
- **Item Highlights are not checked by the trademark pack**, and the console listing editor does not provide an
  `item_highlights` input field.
- **The ARM64 image is not scanned separately by Trivy.** The workflow scans the amd64 image, then builds and pushes
  the multi-platform manifest.
- **Two Spring Framework 6.2 findings are temporarily ignored by the release image scan.** `CVE-2026-47884` is fixed
  in Spring Framework 7.0.9 or later, but has no patched Spring 6.2 OSS release; it requires `XsltView` and a
  catch-all mapping that renders a view without an explicit view name. Listing Guard has no XSLT view resolver or
  catch-all view-rendering route. `CVE-2026-47890` is fixed in Spring Framework 7.0.9 or later, with no patched Spring
  6.2 OSS release; it requires SSE with view fragments, and the application exposes no SSE endpoints. Both Trivy
  exceptions expire on 2027-01-31. A Spring Boot 4 / Spring Framework 7 migration is planned as a separate PR for
  v0.7.0; reassess and remove the exceptions then.
- **MCP HTTP has no authentication.** It is disabled by default and refuses wildcard/public bind addresses, but can
  bind a private-network address. Prefer loopback; add authentication before allowing other machines on a private
  network to connect. A non-loopback API base URL must use HTTPS unless
  `LISTING_GUARD_MCP_ALLOW_INSECURE_HTTP=true` is explicitly set for a trusted private network.
- **Reports cannot reconstruct expired history.** Trademark, variation and personalization results are retained for
  30 days by default, so longer report periods can have incomplete coverage. The job's `report.json` is the saved
  report; there is no rollup table. Cache hits are not counted. The console is currently English while the job report
  is Vietnamese; a shared Vietnamese interface and a configurable `top` parameter (maximum 50) are future work.
  Personalization matched marks are not listed in reports, and the maximum report period is 92 inclusive days.
- **The shipped trademark catalog is DEMO only.** It contains fictional marks and is for local testing and
  demonstrations; production deployments must import and configure their own catalog.
- **Oracle A1 capacity and availability are not guaranteed.** The documented 2 OCPU / 12 GB resources are shared
  with PostgreSQL, the API, cloudflared and optional Preview; actual capacity and reclaimed-instance risk depend on
  Oracle account quota and availability.

## Image

The release workflow publishes:

- `ghcr.io/thanhdatpb/listing-guard:0.6.0`
- `ghcr.io/thanhdatpb/listing-guard:latest`

Both tags are multi-architecture images for `linux/amd64` and `linux/arm64`. Set
`LISTING_GUARD_VERSION=0.6.0` in the production `.env`. Image tags through `0.5.0` are amd64-only.

The MCP shaded jar is built with `./mvnw -B -pl mcp-server package` and must be attached manually to the GitHub Release
as `listing-guard-mcp-0.6.0.jar`; the release-image workflow only publishes container images.
